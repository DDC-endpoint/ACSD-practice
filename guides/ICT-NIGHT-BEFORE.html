Part 1: React from zero, enough to read the templates

A component is a function that returns HTML-looking code (JSX). Five pieces cover every template:

function Hello() {                                   // 1. a component is just a function
  const [count, setCount] = useState(0);             // 2. state: a memory box + its setter

  useEffect(() => {                                  // 3. run code after the page shows
    /* fetch here */
    return () => { /* cleanup when the component leaves the screen */ };
  }, []);                                            //    [] = run once, on load

  if (count > 5) return <p>Too many</p>;             // 4. early return = conditional UI
  return <p>Count is {count}</p>;                    // 5. {curly braces} = put JS inside JSX
}
  • useState(0) returns two things. One is the current value and the other is a function that changes it. Changing it makes React redraw.
  • useEffect(fn, []) means "after the first render, run fn once". The function you return from it is the cleanup.
  • JSX looks like HTML, but {} lets you drop a JS value into it.

Template 1: Router config with a shared layout (D1a, 4 marks; D1b)

import { BrowserRouter, Routes, Route, Outlet, Link } from 'react-router-dom';

function Layout() {
  return (
    <>
      <nav>
        <Link to="/">Home</Link>
        <Link to="/students">Students</Link>
        <Link to="/settings">Settings</Link>
      </nav>
      <main>
        <Outlet />
      </main>
    </>
  );
}

export default function App() {
  return (
    <BrowserRouter>
      <Routes>
        <Route path="/" element={<Layout />}>
          <Route index element={<Home />} />
          <Route path="students" element={<StudentList />} />
          <Route path="students/:studentId" element={<StudentDetails />} />
          <Route path="settings" element={<Settings />} />
          <Route path="*" element={<NotFound />} />
        </Route>
      </Routes>
    </BrowserRouter>
  );
}
  • index is the child shown at the parent's own path (/), so it is the home page.
  • Child paths have no leading /: students becomes /students.
  • :studentId is a dynamic segment. It matches /students/1, /students/42 and so on.

D1b, the purpose of <Outlet />: it is a placeholder in the parent layout where the matched child route's component renders, so the shared navigation menu stays on screen and only the page content inside it changes.

Template 3: Navigate after an action (D1d, 2 marks)

import { useNavigate } from 'react-router-dom';

function PreferencesForm() {

Template 4: Fetch on load with AbortController (D2b, 6 marks)

import { useEffect, useState } from 'react';

interface Course { id: number; title: string; }

export function CourseCount() {
  const [courses, setCourses] = useState<Course[]>([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState<string | null>(null);

  useEffect(() => {
    const controller = new AbortController();

    async function load() {
      try {
        const res = await fetch('https://example.com/api/courses', {
          signal: controller.signal,
        });
        if (!res.ok) throw new Error(`HTTP ${res.status}`);
        const data: Course[] = await res.json();
        setCourses(data);
      } catch (err) {
        if (controller.signal.aborted) return;   // unmounted: touch no state
        setError(err instanceof Error ? err.message : 'Request failed');
      } finally {
        if (!controller.signal.aborted) setLoading(false);
      }
    }

    load();
    return () => controller.abort();   // cleanup runs on unmount
  }, []);

  if (loading) return <p>Loading courses...</p>;
  if (error) return <p>Error: {error}</p>;
  return <p>There are {courses.length} courses.</p>;
}

Skeleton to say out loud: 3 states → the effect → the controller → async function load with try / catch / finally → call load() → return the abort → 3 if/returns.

  • fetch does not reject on 404 or 500. It rejects only on a network failure or an abort, so check res.ok yourself.
  • res.json() also returns a Promise, so await it.
  • The effect callback can't itself be async, because it must return nothing or a cleanup function, not a Promise. So define async function load() inside it and call it.

D2a, why async: a network request takes time. An asynchronous call lets the app keep running and stay responsive, then handle the response when it arrives, instead of freezing while it waits.

D2c, why an API service module: it keeps the fetch logic for an endpoint in one place, so every component reuses the same code, and a change to the URL, headers or error handling happens once. It also separates API logic from UI logic.

Part 3: Plain-JS answers (D3, 10 marks)

D3a: Validation function (4 marks)

function validateEvent(form) {
  const errors = {};

  if (form.name.trim() === '') {
    errors.name = 'Event name is required.';
  }
  if (form.location.trim() === '') {
    errors.location = 'Location is required.';
  }
  const max = Number(form.maxAttendees);
  if (!Number.isInteger(max) || max <= 0) {
    errors.maxAttendees = 'Maximum attendees must be a positive whole number.';
  }

  return errors;   // {} means valid
}
  • .trim() makes " " count as empty.
  • Number('') is 0, so an empty field fails max <= 0. Number('abc') is NaN, and Number.isInteger rejects it and 2.5.
  • "Positive" excludes 0, so the check is <= 0.

D3b: POST with headers and JSON (3 marks)

async function createEvent(event) {
  const res = await fetch('/api/events', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(event),
  });
  if (!res.ok) throw new Error(`Create failed: ${res.status}`);
  return res.json();   // usually the created event (201 Created)
}
  • Content-Type: application/json tells the server the body is JSON.
  • JSON.stringify turns the object into a JSON string. fetch can't send a plain object.
  • If the API needs a login, add Authorization: `Bearer ${token}` to the headers.

D3c: POST vs PUT (3 marks)

POST sends a new record to the collection URL (/api/events). The server creates it, assigns its id and usually replies 201, so sending it twice creates two events. PUT sends the full updated record to that record's own URL (/api/events/7) and replaces it, so it is idempotent: sending it twice gives the same result. A frontend uses POST for "create" forms and PUT (or PATCH, for a partial change) for "edit" forms.

Part 4: TanStack Query and Zustand (D4, A11, A12, A15, B6, B7, B14, C4)

The D4a rule: if the server owns the data, use TanStack Query. If the browser owns it, use Zustand. They are not interchangeable (B14 is false).

TanStack Query: server state (products, profiles, anything from an API)

const { data, isLoading, error } = useQuery({
  queryKey: ['products'],          // cache label
  queryFn: () => fetch('/api/products').then(r => r.json()),
  staleTime: 60_000,               // fresh for 60s, so no refetch
});

const queryClient = useQueryClient();
const update = useMutation({
  mutationFn: (p) => fetch(`/api/products/${p.id}`, { method: 'PUT', body: JSON.stringify(p) }),
  onSuccess: () => queryClient.invalidateQueries({ queryKey: ['products'] }),
});
  • Caching (D4b): results are stored under the queryKey. Any component that asks for the same key gets the stored data at once, without a new request. The benefit is fewer network calls, a faster UI, shared data, and loading and error states for free.
  • staleTime (A11): how long cached data counts as fresh. The default is 0.
  • invalidateQueries (A15, C4, D4c): marks matching cached queries as stale, so they refetch. Call it in the mutation's onSuccess.

Zustand: client state (cart, theme, sidebar open)

const useCartStore = create((set) => ({
  items: [],
  add: (item) => set((s) => ({ items: [...s.items, item] })),
}));

const items = useCartStore((s) => s.items);   // selector
  • create returns a hook, and you use it to read the store (A12).
  • Selector (D4d): subscribes the component to one slice only, so it re-renders only when that slice changes. This avoids needless re-renders, and it is why B7 is false.

Part 5: Gap sheet (lecture topics the practice pack misses)

The mock asked none of these except security, so do this last, in about 20 minutes. It comes from the lecturer's own slides.

L01: How the web works

  • Internet vs WWW: the Internet is the network infrastructure (TCP/IP). The WWW is one service that runs on it.
  • IP: every device has an IP address. IPv4 is 32-bit (about 4.3 billion addresses). IPv6 is 128-bit.
  • TCP: reliable delivery plus ports, so many programs can share one IP. FTP is 21, SMTP 25 and HTTP 80. Games and streaming use the simpler UDP.
  • DNS: turns a name into an IP address (nslookup www.google.com).
  • What happens when you type a URL: DNS gives the IP, the browser connects on port 80, sends GET /path, then renders the page.
  • HTTP: a request-response protocol in the client-server model. Lecture codes: 200 OK, 301 moved, 403 forbidden, 404 not found, 500 server error.
  • Traditional vs SPA: a traditional site has the server send a new HTML page on every click. An SPA loads the app shell once, then JS swaps the views and gets data as JSON.
  • MVC: the Model is the data classes, often one per DB table (C#). The Controller handles HTTP requests and holds the CRUD methods (ControllerBase, [ApiController]). The View is the UI. In CampusEvents, React is the View.
  • DTO (Data Transfer Object): sends only what the client needs. Why use one: you don't leak fields like PasswordHash, you don't send data React doesn't need, and the API isn't tied to the DB model, so a model change doesn't break the API.
  • Cookie: the server sets it and the browser sends it back automatically. Session: the server stores the user's info and gives the browser a session ID. JWT: the server signs a token with claims, and the client sends it back on each request.

L03: Consuming APIs

  • CORS: a different origin means a different protocol, domain or port. React on localhost:5173 calling the API on :5229 is cross-origin. Browsers block it by default, so the API (server) must allow the frontend origin. In ASP.NET that's AddCors(...WithOrigins(...)) and UseCors before auth. Postman and Swagger aren't browsers, so CORS never applies to them.
  • The four UI states: loading, success, error and empty. Zero results is a success, not an error.
  • Why a useEffect callback can't be async: an async function always returns a Promise, but useEffect expects nothing back, or a cleanup function. So define async function load() inside the effect and call it.
  • Service → Hook → Component: the service does the HTTP, the hook holds the state, and the component shows the UI. This separates responsibilities and keeps fetch logic in one place.

L05: Routing, forms, CRUD (extras beyond the mock)

  • <Link to> vs navigate(): a link is for the user to click, and navigate() is for after an action. Don't use <a> for internal links, because it reloads the whole page.
  • Catch-all route: path="*" shows a NotFound page. A valid route can still be a missing record: /events/999 can return 404 from the API.
  • Controlled input: value={title} plus onChange={e => setTitle(e.target.value)}. React state is the source of truth.
  • Zod (from the lecture slide), used with React Hook Form: z.object({ title: z.string().trim().min(1, "Enter a title"), capacity: z.coerce.number().int().positive() }).
  • PUT vs PATCH: PUT replaces the whole record. PATCH changes only part of it.
  • fetch does not reject on 400 or 500. Always check res.ok.
  • Delete: run window.confirm, then send DELETE, then refresh the list only if it succeeded.
  • Folders: pages/ holds route views, components/ reusable UI, services/ HTTP, plus hooks/ and types/. Read the base URL from import.meta.env.VITE_API_URL.

L07: Auth (deeper than the mock)

  • A JWT has three parts: header.payload.signature. It's Base64URL-encoded, which is not encryption: it's signed, not encrypted, so never put secrets in it.
  • Claims: sub (user id), email, exp (expiry), iss (issuer), aud (audience), role.
  • Authenticated request: the header is Authorization: Bearer <token>. Attach it in one central place, the API service.

  • Protected route: if not logged in, return <Navigate to="/login" replace />; otherwise return <Outlet />.

L04: HTML5, CSS3, Bootstrap

  • Page setup: <!DOCTYPE html> gives standards mode, not quirks mode. <html lang="en"> helps accessibility and SEO. <meta charset="UTF-8"> sets the character encoding. <meta name="viewport" content="width=device-width, initial-scale=1.0"> is needed for responsive design.
  • Semantic tags: header, nav, footer, aside (sidebar). section is a themed group, while article is standalone content you could share on its own. Also figure/figcaption, details/summary, time datetime="" and mark. progress shows task progress, while meter shows a value in a range, such as disk usage.
  • Bootstrap basics: it's mobile-first and responsive. A CDN copy is often already cached and comes from a nearby server. JS is needed only for interactive parts (modals, tooltips, dropdowns, through Popper). Bootstrap 5 doesn't need jQuery, even though the slide mentions it.
  • Containers: .container is fixed width, .container-fluid is full width.
  • Grid: 12 columns, nested as .container → .row → .col-*. Breakpoints: sm ≥576, md ≥768, lg ≥992, xl ≥1200, xxl ≥1400px. col-sm-4 takes 4/12 of the width from sm up and stacks on smaller screens. The columns in a row should add up to 12.
  • Classes to recognise:
    • colour: bg-success, text-white, text-muted/primary/danger
    • components: btn btn-primary, alert alert-success, card/card-body/card-title, table, btn-group
    • img-fluid (responsive image), spinner-border, progress/progress-bar, pagination/page-item/page-link
    • spacing: m/p + t/b/s/e/x/y + 0–5, for example py-4
    • display: d-none d-md-block
  • Optimisation: minify (strip whitespace and comments), bundle (fewer HTTP requests), compress images and use srcset, use a CDN, and lazy load (loading="lazy").

Exam technique (from the exam-day guide)

  • Absolute words usually make a statement FALSE: guarantees, never, always, every, exclusively, requires every, interchangeable, automatically trustworthy.
  • Soft words usually make it TRUE: can, may, generally, helps, can be used.
